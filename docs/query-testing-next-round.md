# 검색 Query 다음 검증 라운드

작성일: 2026-09-05. 상태: 검증 제안. 아래 내용은 실행 결과나 알고리즘 적용 완료를 뜻하지 않는다.

## 요청과 현재 확인 범위

- 사용자 요청: 중간 음높이 변경과 음 생략 외에 검색 개선 방향 및 추가 Query 테스트를 제안한다.
- 개별 정본 JSON은 Q-P1-002~005 네 개이며 모두 melody_rhythm / 4/4 / absoluteExactOnly=false다. 이는 과거 사용자 테스트 전체의 수가 아니라 현재 개별 파일로 정리된 수다.
- Porgy Q-P1-001과 변형은 legacy JSONL에 보존되어 있지만 현재 export 대상인 개별 JSON에는 포함되지 않는다. 개발 기록의 사례도 추가 이관이 필요하다.
- 전조·이명동음·exact·박자·프레이즈·삽입/삭제 등 단위 테스트는 존재한다. 실제 코퍼스에서 정답 작품·파트·구간·오탐까지 검증한 것과는 구별한다.
- 이번에는 검색 코드·임계값·DB를 바꾸지 않는다. 특정 작품을 상위에 고정하지 않고 오류 유형별로 개선 여부를 판단한다.

## 테스트 원칙

1. DB에 있는 실제 선율의 원형부터 검색한다. 원형이 누락되면 수록 여부, 파싱, 후보 생성, 최종 필터를 먼저 구분해서 진단한다.
2. 같은 원형에서 한 요인만 바꾸고, 허용할 변화와 구별해야 할 변화를 짝으로 비교한다.
3. 초기에는 8~16음 정도의 실제 선율을 사용하되 최소 입력 수를 늘리는 제품 변경은 하지 않는다. 짧거나 반복적인 Query는 별도의 모호성 테스트로 다룬다.
4. 작품 회수뿐 아니라 실제 파트·보이스·마디·붉은 음표의 정확성을 판정한다. 구조적 매치는 보조음 생략의 근거도 확인한다.
5. 임의 Query가 전 코퍼스에 없다고 단정하지 않는다. 부정 사례는 특정 잘못된 결과를 검토하거나 확인된 제한 코퍼스로 만든다.
6. 기존 튜닝 작품과 별도로 처음 보는 작품을 남겨 검증한다. 같은 작품의 다른 편곡도 튜닝용과 검증용으로 무심코 나누지 않는다.

## 우선 테스트 목록

| 순서 | 비교할 사례 | 판정할 내용 |
|---|---|---|
| 1 | 짧은 약박 장식음 생략 ↔ 길고 중요한 강박 음 생략 | 전자의 회수는 유지하고 후자는 더 큰 불일치로 다룬다. 강박이면 무조건 기둥음은 아니며 앞 프레이즈 타이 잔음 등의 문맥도 확인한다. |
| 2 | 3/4·6/8, 못갖춘마디·쉼표 뒤 실제 시작 ↔ 앞 프레이즈 타이 잔음까지 포함한 시작 | 실제 박자 계층과 첫 공격 위치를 찾는지 검사한다. 6/8을 단순히 4/4 강박 위치로 평가하지 않아야 한다. |
| 3 | 원형 ↔ 전체 음가 ×2 ↔ 작은 국소 리듬 변화 ↔ 강세·쉼표 위치의 큰 변화 | 유사 검색에서 균일한 확대와 작은 변화는 안정적으로 회수하고 비슷한 멜로디 사이의 큰 리듬 차이는 구별한다. Exact의 음가 확대 정책은 별도로 정의한다. |
| 4 | 긴 음 하나 ↔ 같은 pitch의 tie로 분할 ↔ tie 없이 두 번 재타격 | tie는 하나의 sounding event, 재타격은 다른 사건이다. 검색·색칠·재생이 같은 해석을 쓰는지 확인한다. |
| 5 | 첫 음/중간 음/마지막 음 각각 변경; 같은 선율 6→10→16음 확장 | 경계의 작은 오류로 통째로 탈락하는지 확인한다. 올바른 후속 음을 추가할 때 회수 안정성을 보되 순위의 단조 상승을 요구하지는 않는다. |
| 6 | 반복음 개수·위치까지 맞는 원형 ↔ 특징적 도약이나 반복 위치만 변경 | 흔한 패턴보다 드문 특징의 일치가 중요하다. 결과 개수를 채우기보다 거짓 고득점 억제를 평가한다. |
| 7 | 실제 내성부 연속 선율 ↔ 서로 다른 파트에서 한 음씩 임의로 섞은 선율 | 실제 보이스를 회수하고 존재하지 않는 선율을 조립하지 않아야 한다. 다른 악기·반복 마디의 동일 선율은 등장 위치로 묶고 variation은 구별한다. |
| 8 | S/U/D와 step/leap 모두 일치 ↔ 방향만 일치 ↔ 방향 불일치 | 순수 contour에서 방향 일치가 기본 조건, step/leap는 가산 우선순위다. 모드 전환 시 이전 pitch Query가 섞이지 않아야 한다. |

기본 동일성 검사도 별도 묶음으로 유지한다: 전체 조옮김, sharp/flat 이명동음, melody-only와 melody+rhythm의 exact 차이, 쉼표 옵션, 셋잇단음표(쉼표 포함), 검색 결과 내 재검색 범위. 실제 pitch·음가가 같다면 표기 차이만으로 탈락해서는 안 된다.

## 첫 라운드 진행안과 기록

- 원형 세 개: 3/4 또는 6/8의 프레이즈 시작 사례, 당김음/쉼표/타이 사례, 반복음 속 특징적 도약 사례. 가능하면 기존 튜닝 작품 외에서 고른다.
- 각 원형과 단일 요인 변형 네 개, 총 15 Query를 기록한다. 허용 변화/감점 변화/모드별 제외 기대를 실행 전에 정한다. 모든 변형이 같은 순위로 원곡을 찾아야 한다는 뜻은 아니다.
- parentCaseId와 변형 설명을 남긴다. 정답 공개 전에는 기대 결과를 미확정으로 보존하고 관측 결과를 먼저 기록한다.
- 최소 기록: 원본 Query JSON, 모드/옵션, 변형 요인, 기대 작품·파트·마디·음표, 허용 범위, 실제 순위·URL·상위 오탐, 코드/DB 버전, cold/warm 시간, 진단, 수정안, 수정 전후 실행 결과.
- 작품 Top 1/5/10 회수와 잘못된 고득점 결과, 구간·음표 정확성을 함께 본다. MIREX QBSH도 방해 곡을 포함한 정답 곡 Top-10 회수를 평가한다. 본 프로젝트는 악보 위치 검증도 추가한다. 출처: [MIREX Query by Singing/Humming](https://music-ir.org/mirex/wiki/2021:Query_by_Singing/Humming).

## Harness 보완 순서

1. Legacy JSONL와 개발 기록의 사례를 개별 정본으로 이관하고 원본 연결을 보존한다. 중복 case/run 구분을 확인한다.
2. 기대 결과 미확정과 검증 완료를 구별하고 모든 case에 schema 검사를 적용한다. Q-P1-005의 status=fixed 및 누락 필드는 현재 schema와 맞추는 작업이 남아 있다.
3. Production 검색 경로의 전체 verified suite 보고서를 완성한다. 합성 테스트나 단위 테스트 통과를 실제 전체 검색 성능으로 표시하지 않는다.
4. 누락 원인을 파싱/후보 생성/정렬/최종 필터로 나누어 기록한다. 후보에 없는 정답은 가중치 조절만으로 해결되지 않는다.
5. 정확도·오탐·성능을 비교한 뒤 필요한 알고리즘 변경만 진행한다. 특정 Query나 작품 ID의 순위를 고정하지 않는다.

## 프레이즈 분석과 사람 분석 데이터의 관계 (2026-09-05)

사용자는 별도 프로젝트에서 사람의 음악 분석 데이터를 수집 중이며, 그 데이터 없이 프레이즈를 제대로 찾을 수 있는지 질문했다. 아래는 조사 및 설계 권고이며 분석기 구현 완료를 뜻하지 않는다.

### 현재 구현과 한계

- server/search-api.mjs의 annotateStructural은 국소 pitch 진행, 상대 음가, 박자, tie/new attack, 쉼표, cue를 사용한다. phraseOpeningConfidence/phraseClosingConfidence는 주로 앞뒤 쉼표와 타이·긴 음의 규칙 조합이다.
- 이는 화성·종지·반복 구조를 함께 분석한 프레이즈 분할기나 완전한 셴커 분석이 아니다. passing/neighbor도 화성 확인 전의 형태적 추정이다.
- 현재 work.analysisConfidence=.72, corpus note.structuralConfidence=.65는 고정값이므로 검증된 정확도 확률로 해석하면 안 된다. 향후 계산 근거 및 보정된 confidence와 구분해야 한다.

### 사람의 대규모 학습 데이터 없이 가능한 방법

1. 먼저 원본의 part/staff/voice, 박자 변화, 실제 onset/offset, 타이 최초 어택과 지속 조각을 정확히 보존한다. 강박에 이어진 타이 조각을 새 프레이즈 어택으로 세지 않는 판단은 완전한 화성 분석 없이도 가능하다.
2. LBDM처럼 pitch interval, IOI, 쉼표의 국소 변화에서 경계 후보를 구한다. 국소 그룹 경계가 곧 종지로 닫히는 프레이즈라는 뜻은 아니다.
3. 곡 내부 반복의 시작/끝, 리듬 재시작, 호흡 기호, 텍스처·음역 변화 등 독립 단서를 결합한다. 슬러·가사 줄바꿈·긴 음 하나를 경계의 확정 근거로 사용하지 않는다.
4. 화성·베이스·성부진행 분석을 붙일 수 있을 때 종결/지속 후보를 추가하고 경계를 재평가한다. 종지와 프레이즈가 서로의 초기 출력을 확정 정답으로 삼지 않게 한다.
5. 국소 경계, 프레이즈, 섹션, 셴커식 구조적 축약은 서로 다른 수준이다. 섹션 분할 모델의 성능을 프레이즈/중경 분석 성능으로 대신 제시하지 않는다.

연구 근거: [Cambouropoulos, LBDM (2001)](https://ofai.at/papers/oefai-tr-2001-11.pdf)는 국소 변화 기반 경계를 제안하며 화성·반복 정보가 없는 한계를 명시한다. [Rodríguez-López et al., Multi-strategy Segmentation (2014)](https://research-portal.uu.nl/en/publications/multi-strategy-segmentation-of-melodies)는 여러 경계 단서를 결합해 사람 주석과 비교했다. 이 연구들의 성과가 현재 혼합 코퍼스의 정확도를 보장하지는 않는다.

### 검색 연결 권고

- 기본 연속 선율 검색은 유지한다. Query는 프레이즈의 중간 일부일 수도 있고 경계를 가로지를 수도 있으므로 분석된 프레이즈에만 검색을 가두지 않는다.
- 경계는 후보와 근거 강도로 저장한다. 보정 전 규칙 점수를 정답 확률로 표시하지 않는다. 신뢰할 만한 경우에만 시작/끝 대응과 기둥음 비교의 보조 점수에 사용하고, 애매하면 중립 처리한다.
- 앞 프레이즈의 타이 잔음을 새 공격으로 세지 않는 것과 그 음을 화성적으로 중요하지 않은 보조음이라고 단정하는 것은 다르다. 지속음은 화성 문맥에서 계속 평가한다.
- 자동 분석은 가능하면 원곡 문맥을 보고 사전 계산·버전 캐시한다. Query와 잘 맞는다는 이유로 원곡 경계를 바꾸거나 임의의 음을 구조음으로 선택하지 않는다.
- 분석 없이/국소 단서만/여러 단서 결합의 비교 실행으로 정답 회수·오탐·첫 공격·붉은 음표 정확성을 확인한다. 분석 추가가 실제 검색을 개선했는지가 별도 검증 항목이다.

### 다른 프로젝트의 사람 분석 데이터 연결

- 대규모 학습셋 완성을 기다릴 필요는 없다. 먼저 독립적으로 주석한 일부 구간을 검증용으로 사용하고, 애매하거나 모델 간 의견이 다른 구간을 사람 검토 우선 대상으로 제안한다.
- 작품/판본 ID 및 원본 hash, part/staff/voice, 마디 ordinal과 표시 번호, 마디 내 onset, 원본 음표 ID 및 sounding-event 연결을 공유한다. 현재 인덱스 순번만으로 연결하면 재파싱 때 깨질 수 있다.
- 사람 분석은 자동 추정과 별도 계층으로 저장하고 출처·분석자·버전·불확실성·대안 해석을 보존한다. 검토된 운영 주석을 우선 사용할 수 있으나 held-out 정답은 테스트 검색기의 입력에 넣지 않는다.
- 같은 작품의 전조/편곡/반복 구간이 학습과 평가 양쪽에 섞이지 않게 분할한다. 학습 주석 없이 규칙은 만들 수 있지만, 잘 분석한다는 입증에는 별도의 사람 평가가 필요하다.
