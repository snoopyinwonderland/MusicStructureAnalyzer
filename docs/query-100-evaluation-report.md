**테스트 환경**: MUSICANOTE 코퍼스 95,625 Works / 384,425 Streams (SQLite DB 28.4GB)

**표기 기준**: `음높이(음가)` 형식 (예: `C4(1)` = 가온다 4분음표 1박, `Rest(0.5)` = 8분쉼표 0.5박, `A4(0.5)~` = 타이 연결)

## 2026-09-06 구현 대조 검토

이 절은 아래 원 보고서의 확정적 표현보다 우선한다. 표의 300개 Query는 유용한 변형 후보군이지만, 실측했다고 서술된 것은 76개이며 실행 당시 Query JSON, 정확한 work/source/stream ID, 대상 onset, 결과 snapshot, 코드 hash와 DB 식별 정보가 없다. 따라서 76.3%는 현재 재현 가능한 제품 성능 지표가 아니며, 목표 제목과 마디도 독립 확인 전에는 `verified` 정답으로 사용하지 않는다.

- **채택**: 중간 오음·장식음·tie·쉼표·전역 tempo scaling·반복 occurrence·짧고 저정보인 Query 등 30개 변형 범주를 Harness 입력 후보로 보존한다. 표 300행은 `scripts/import-query-100-report.mjs`로 `evaluation/generated/query-100-report.jsonl`에 `draft` 상태로 정규화한다. meter와 `startsOnDownbeat`는 보고서에 없으므로 추측하지 않고 각각 `unknown`, `null`로 둔다.
- **현재 구현과 일치**: tie는 하나의 sounding event로 병합하고, 후보에 들어온 뒤에는 IOI/rhythm DTW, 기둥음·박자·프레이즈 단서를 제한적으로 사용한다. 반복 occurrence는 작품/파트별 등장 마디로 묶는다. 이 사실이 아래 개별 성공의 원인을 단독으로 입증하는 것은 아니다.
- **재현 후 반영**: Q007/Q010/Q031의 구간 오정렬은 원본 stream과 target onset을 붙여 note precision/recall로 확인한다. 완전히 같은 반복이라면 무조건 첫 마디를 고르기보다 Query의 경계·박자 문맥을 먼저 비교하고, 근거까지 동률일 때만 앞 occurrence를 안정적인 tie-break로 사용한다.
- **별도 인덱스 실험**: Q011/Q012/Q016 및 BWV114처럼 후보 생성 전에 사라지는 사례는 m3/s3 계열 후보 채널의 근거가 된다. 하지만 현재 `structuralWeight`는 화성 분석이 없는 휴리스틱이며, 재현율을 보장한다고 표현하지 않는다. 새 DB를 별도로 구축해 표면 선율 회수와 오탐을 함께 비교한 뒤 채택한다.
- **보류/거절**: 저음역만으로 베이스를 감점하지 않는다. 실제 저성부 선율도 검색 대상이므로 part/voice provenance, 반복성, 음가, texture와 melody-role을 함께 본다. 음정 반전은 원 선율과 방향이 반대이므로 일반 melody 검색의 정답 회수 목표로 삼지 않는다. `mod 12` 옥타브 바운스와 2-gram 초단문 완화는 오탐 폭증 위험이 있어 독립 옵션/실험 없이 기본 검색에 넣지 않는다.
- **UI 문구 교정**: interval exact만으로 해당 구간을 작품의 “주제부” 또는 음악적으로 100% 같은 선율이라고 단정하지 않는다. 현재처럼 조옮김 불변 음정, 정렬 삽입·누락, rhythm, downbeat와 구조 근거를 각각 설명한다.

이관 자료는 언제든 다시 만들 수 있다: `npm run harness:import-query-100`. 사람 확인으로 source/stream/구간이 보완된 사례만 개별 `evaluation/cases/*.json` 정본으로 승격한다.

## 1. 평가 배경 및 판정 원칙

본 문서는 데이터베이스 내의 실제 악곡 멜로디(6~20음)를 바탕으로 사용자의 인지적 오류, 표기 차이, 리듬 변형을 반영한 **300개의 벤치마크 쿼리 (1부 100개 기초 변형 + 2부 100개 쉼표·도약 특화 + 3부 100개 인지 왜곡 및 구조 변형)**를 구축하고, 이를 실제 검색 엔진에 실행하여 **"빨간색 표시(Alignment) 오류"** 및 **"검색 결과의 문제점"**을 실측 분석한 보고서입니다.

### 판정 원칙 (사용자 관점 반영)
음악 정보 검색(MIR)에서 변형된 쿼리를 입력했을 때:
1. **정당한 상위 점유 (Legitimate Match, 정상)**: 사용자가 가한 변형(오음, 못갖춘마디 생략 등)으로 인해, 변형된 쿼리와 **음악적으로 더 완벽하게 부합하는 실제 다른 악곡**이 코퍼스에 존재하여 1~2위를 차지한 경우는 **검색 엔진의 실패가 아니라 정밀한 선율 일치**로 판정합니다.
2. **진짜 결함 사례 (Problematic Cases)**:
   - **악보 빨간색 하이라이트(Alignment) 오정렬 (`MEASURE_MISALIGNED`)**: 원곡을 찾았음에도 실제 의도한 구간이 아닌 엉뚱한 마디(예: 후반부 반복 마디)에 매칭되어 빨간 음표가 엉뚱한 자리에 칠해지는 경우.
   - **비선율성 텍스처 오탐 (`TEXTURE_FALSE_POSITIVE`)**: 16분음표 분산화음 반주나 단순 베이스 지속음이 높은 멜로디 점수로 주선율을 밀어내는 경우.
   - **조기 탈락 (`MISSED / ZERO_RECALL`)**: 원곡과 멜로디 유사도가 충분히 높음에도 1단계 n-gram 임계치나 사소한 리듬 차이로 20위 밖으로 완전히 소실되는 경우.
   - **부당한 과도 생략 (`SPARSE_OVER_SKIPPED`)**: 핵심 기둥음이 부당하게 건너뛰어져 띄엄띄엄 단편적인 음들만 억지로 꿰어 맞춘 경우.

* **분석**: 원곡의 바운스 리듬을 셋잇단음표 스윙(`0.667:0.333`)으로 입력했음에도 **모두 1위로 완벽 검출**되었습니다. 리듬 정렬기가 경미한 비율 차이(0.5 vs 0.667)를 페널티 없이 탄력적으로 흡수하여 연주 스타일 차이에 매우 강인함을 실증했습니다.

#### C. 극단적 옥타브 이주(±24, ±36반음)의 완벽한 불변성 (`ULTRA_OCTAVE_SHIFT`)
* **실측 결과**: **Q221 (`When a Man Loves a Woman`)** 1위(Rank 1), **Q222** 1위(Rank 1).
* **분석**: 피콜로/휘파람 초고음 음역대(+24반음)나 초저음(-24반음)으로 완전히 옮겨서 입력해도 검색 엔진의 1단계 n-gram 인덱스가 절대 음고가 아닌 **상대 음정(Relative Semitone Interval)**을 키값으로 사용하므로 100점 만점으로 정확하게 1위를 유지합니다.

#### D. 동음 연타 압축(Repeated Pitch Compression)에 대한 놀라운 회수력
* **실측 결과**: **Q231 (`WHO WOULD IMAGINE A KING`)** 1위(Rank 1), **Q232** 1위(Rank 1).
* **분석**: "솔-솔-솔-미"처럼 동음 연타를 1개의 긴 음표로 압축했음에도 1위로 회수되었습니다. 유니슨(0반음) 음정이 병합되어도 주변의 도약 및 스텝 음정 골격이 보존되어 시드가 온전히 살아남았습니다.

#### E. 헤미올라 및 복합박자(3/4 vs 6/8) 착각에서의 회수력 (`HEMIOLA_METRIC_AMBIGUITY`)
* **실측 결과**: **Q271 (`A DREAM IS A WISH YOUR HEART MAKES - 신데렐라`)** 1위(Rank 1), **Q272** 1위(Rank 1).
* **분석**: 3/4박자와 6/8박자의 그루핑 착각으로 리듬 길이가 1.5배/0.75배로 왜곡되었으나, 음정 완벽 일치가 리듬 왜곡 감점을 압도하여 1위를 유지했습니다.

#### F. 음정 대칭 반전(Interval Inversion Mirror)의 구조적 탈락 (`MISSED`)
* **실측 결과**: **Q251 (`YOU CALL IT LOVE`)**, **Q252**: 20위 밖 탈락 (`Rank 0`).
* **분석**: 인간이 멜로디의 상행/하행 방향을 반대로 기억하여 입력한 경우(+3반음이 -3반음으로 반전), 부호에 민감한(Sign-sensitive) 1단계 n-gram이 100% 불일치하여 단 하나의 시드도 생성하지 못하고 조기 탈락합니다.
* **개선책**: 윤곽 전용 인덱스(Contour Index: U/D/R)를 보조 채널로 도입 검토.

## 7. 결론 및 향후 개선 로드맵

1. **빨간색 하이라이트 오정렬 해결**:
   - 동일 모티프/코드 반복 곡의 경우 가장 앞선 마디(First Occurrence)를 우선 바인딩.
   - C2/D2 등 극저음 지속 베이스 파트의 멜로디 스트림 선출 기준 엄격화.
2. **순차 진행 팝 발라드의 오음 저항성 확보**:
   - 강박 골격(`m3`) 및 셴커 기둥선(`s3`) 역색인을 추가하여 중간 1~2음 오음 시에도 후보 풀 생존 보장.
3. **음정 반전(Mirror Inversion) 및 옥타브 바운스 대응**:
   - 상대 윤곽(Contour: Up/Down/Repeat) 보조 색인 및 `mod 12` 옥타브 동등성 채널 검토.
4. **초단문(6음) 쿼리 구제책**:
   - 6음 미만 초단문 입력 시 2-gram 허용 또는 리듬 IOI 기반 다이나믹 프로그래밍(DP) 완화 탐색.
5. **정당한 상위 점유 곡에 대한 UI 설명력 강화**:
   - 1위 곡의 결과 카드에 *"입력하신 선율의 음정 진행이 이 작품의 주제부와 100% 일치합니다"*와 같은 음악이론적 근거를 명확히 제시하여 사용자 납득도 제고.
