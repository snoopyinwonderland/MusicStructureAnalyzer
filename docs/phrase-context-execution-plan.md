# 프레이즈 문맥 기반 검색 개선 실행 계획

작성: 2026-09-05. 근거: query-testing-next-round.md와 사용자 Analysis Harness Guide 1.1. 사람 주석을 수집하는 별도 프로젝트와 연결 가능한 보조 분석 계층을 만든다.

## 목표와 금지사항

- 목표: 원곡의 실제 attack·쉼표·국소 변화·반복 근거를 사용해 프레이즈 문맥이 더 자연스러운 유사 결과를 우선한다.
- 원래 연속 선율 검색 및 정확 일치 정의는 보존한다. Query가 프레이즈 일부이거나 경계를 가로질러도 허용한다.
- 후보 수를 채우기 위한 완화, 작품/Query별 순위 고정, 임의 성부 조립, 근거 없는 음 생략을 추가하지 않는다.
- 새 분석은 국소 경계의 규칙 기반 evidence이며 확정 프레이즈·종지·셴커 분석이 아니다. strength를 검증된 정답 확률이라고 표시하지 않는다.

## 단계별 작업과 완료 기준

| 단계 | 작업 | 검증 및 완료 기준 |
|---|---|---|
| 0. 재현 기준선 | 기존 테스트, 실제 검색 A/B runner, legacy 사례 이관 및 export 검증 | Query·코드·DB 식별 정보와 순위/정렬 음표를 재현 가능하게 저장. 미확정 기대값 및 불완전 Query는 별도 표기 |
| 1. 보수적 경계 근거 | tie/new attack, 상대 시간 간격, 국소 pitch/IOI 변화, 제한된 반복 신호를 독립 모듈로 계산 | 전조·시간 확대 불변성, 3/4·6/8·못갖춘마디, 자른 양끝, 타이 지속음, 반복 저정보 패턴 회귀 검사 |
| 2. 제한적 검색 연결 | 원곡 전체 stream 문맥에서 요청당 한 번 분석하고 대응한 내부 경계만 비교 | 멜로디+리듬 유사 검색의 최종 순위에만 최대 ±3점. 후보/정렬/통과 조건 그대로. melody-only·contour·absoluteExactOnly는 영향 없음 |
| 3. 사용자 사례 검증 | 새 곡 원형 3개와 한 요인 변형 4개씩, 총 15 Query | 작품 Top1/5/10뿐 아니라 경쟁 오탐·첫 공격·실제 파트/음표 판정. 단위 테스트 성적을 corpus 정확도로 대체하지 않음 |
| 4. 분석 프로젝트 연결 | 판본/source hash·part/staff/voice·마디 ordinal/onset·음표/sounding-event 대응키와 provenance 합의 | 원본 추적 가능한 사람 분석 일부를 독립 평가용으로 연결. 평가 정답은 검색 입력/튜닝에 누출하지 않음 |
| 5. 확장 판단 | 실패 사례에 필요한 화성·종지·반복 계층 분석과 영속 캐시를 선택 도입 | 분석 없음/국소 단서/추가 분석의 정답·오탐·성능 비교에서 이득이 확인될 때만 기본 활성화 |

## 첫 구현의 상세 규칙

1. 검색된 조각만 분석해 그 양끝을 프레이즈 시작/끝으로 가정하지 않는다. 후보 작품의 part/staff/voice sounding stream 전체를 사용한다.
2. 경계는 음표 사이의 위치로 저장한다. 최초/최종 경계는 바깥 문맥이 없으므로 unknown이다.
3. 타이 continuation을 새로운 어택으로 취급하지 않는다. 화성적으로 중요하지 않다고 단정하는 규칙은 만들지 않는다.
4. 조옮김과 균일 음가 확대에 변하지 않는 상대 신호를 사용한다. 경계 모듈에서 4/4나 일정 마디 길이를 가정하지 않는다.
5. 단일 도약·긴 음·마디 선만으로 확신 높은 프레이즈를 만들지 않는다. 확실한 지속, 경계 후보, 정보 부족을 구분한다.
6. 정렬에서 query/candidate 양쪽 음표가 실제로 인접한 내부 경계만 비교한다. 건너뛴 구간에 존재하지 않는 쉼표/경계를 만들어 비교하지 않는다.
7. 정보가 부족한 후보에 감점을 주지 않는다. 같은 강한 경계 근거는 보조 가산, 명료한 경계와 명료한 연속의 충돌은 제한 감점한다.
8. 원래 selected span과 admission을 유지한 최종 rerank부터 시작한다. 시작 음표 자체를 바꾸는 occurrence 선택 개선은 별도 회귀·사람 검증 후 진행한다.
9. 진단 토글 MUSICANOTE_PHRASE_CONTEXT=0으로 기존 결과를 재현하고 1로 새 근거를 비교한다. 결과에는 계산 방법·지원 근거·감점/가산량·calibrated=false를 남긴다.

## 검증 기준과 보고

- 기존 전체 테스트 기준선: 13개 파일 / 95개 테스트 통과(2026-09-05, 변경 전).
- 기존 실행 가능한 모든 정본 Query를 생산 검색 함수로 전후 비교한다. 제목 기대값이 실제 판본 제목과 불일치하면 미회수로 표시하고 임의 fuzzy 정답으로 보정하지 않는다.
- 결과별 작품/stream, 표시 마디와 ordinal, 실제 target onset:pitch, 순위 및 점수의 변화와 Top100 출입을 보존한다.
- 새 보조 점수는 통과 조건을 변경하지 않지만 출력 상한 근처에서는 순서 변화로 Top100 출입이 생길 수 있으므로 이를 따로 보고한다.
- 실행 시간은 순차 실행의 파일/DB/메모리 캐시 영향을 명시한다. 정확도 측정과 cold/warm 성능 실험을 혼동하지 않는다.
- 자동 테스트 통과와 실제 음악적 개선 확인을 분리한다. 사람 정답 구간이 없으면 "검증 대기"로 둔다.

## 현재 상태

단계 0~2의 첫 구현과 실제 전후 비교를 완료했다. 국소 경계 모듈, 생산 검색 A/B runner, 스키마/export, legacy 사례 이관, 제한적 최종 rerank를 연결했다. 사람 분석 연계 및 새 곡 15 Query 검증, 화성/종지 분석, 영속 경계 캐시와 후보 회수 개선은 미완료 후속 단계다.

## 2026-09-05 첫 적용 결과

- 분석 모듈: server/phrase-boundaries.mjs. 경계 양끝 unknown, 타이 continuation 제외, 상대 pitch/IOI/쉼표 및 제한된 반복 단서, 원래 candidate 인덱스 보존, 불확실한 후보 중립. calibrated=false이며 완전한 프레이즈/셴커 판정이 아니다.
- 검색: melody_rhythm이며 absoluteExactOnly=false일 때 요청당 원곡 stream 전체에서 한 번 계산한다. 새 분석은 선택된 일치 음표·후보 통과 조건을 변경하지 않고 최종 순위만 ±3점 이내 조정한다. MUSICANOTE_PHRASE_CONTEXT=0으로 비활성화할 수 있다.
- 함께 발견된 기존 contour 오류: localAlignment=null일 때 similarity를 직접 읽던 경로를 null-safe로 수정했다. 모드별 통합 검사에 포함했다.
- 정본 7건 중 완전한 Query 6건 실행, 원문 전체가 없는 Q-P1-001-V2 1건은 missing-full-query로 명시적으로 건너뜀. 임의 복원하지 않았다.
- 재실행 명령: npm run harness:phrase. 실제 검색 결과를 케이스별로 저장하므로 중단돼도 완료한 케이스 기록은 남는다. 미확정 기대 곡은 unjudged로 구분한다.

최종 Top100 상한에서 Q001 4개, Q003 4개, Q006 2개가 각각 출입했다. 이는 final rerank에 따른 출력 경계 변화이며 제거된 결과를 전부 오탐으로 판정한 것은 아니다. 단계 3에서 사람 확인이 필요하다.

실행 시간은 baseline 5.8~54.0초, updated 2.5~12.8초였으나 순차 실행과 캐시 영향이 크므로 속도 개선 효과라고 주장하지 않는다. 추가한 profile.phraseContextMs로 분석 비용을 분리 측정할 수 있다.

실행 보고서: evaluation/runs/phrase-context-baseline-2026-09-05-normalized.json 및 phrase-context-updated-2026-09-05-normalized.json. 원본 보고서도 보존했다. 정정본은 보고서의 0-based 순위 표기를 1-based로 바꾸고 BWV772의 확인된 제목 별칭을 평가에만 반영했으며 Query·결과 순서·검색 점수·대상 음표를 바꾸지 않았다. 원래 기대 판정은 originalExpectation에 보존했다.

생산 경로 통합 검사에서는 기존 localSimilarity·scores·대상 음표·마디·scope가 유지되고, melody-only/contour/strict exact가 새 시간 경계 계층과 독립임을 확인했다. 이후 사용자 Query/원곡 주석으로 음악적 타당성을 검증해야 한다.
